Capacity & Performance Targets

Operational SLA and performance expectations for the T-Mobile SCM platform.

Performance Targets

API Endpoints

  • Create Purchase OrderP99 < 500ms / 100 req/sec
  • Get Purchase OrderP99 < 200ms / cache < 50ms
  • Update Purchase OrderP99 < 1000ms / 50 req/sec
  • Query PO ListP99 < 2000ms

Database

  • Query Response TimeP95 < 100ms
  • Connection Pool30 max / 5 min idle
  • Lock Wait< 5s
  • Transaction Time< 5s

Message Queue (Kafka)

  • End-to-End Latency< 5s
  • Throughput10,000 msg/sec
  • Topic Retention7 days
  • Consumer Lag< 1m normal / < 5m alert

Cache (Redis)

  • Hit Rate> 80%
  • Response Time< 10ms
  • Memory Usage< 50 GB
  • TTL30 min default

Batch Jobs (FBDI)

  • Processing Time1-5 mins / 1000 records
  • FrequencyNightly @ 00:30 UTC
  • Success Rate> 99.5%
  • Retry Attempts3

Error Rates

  • HTTP 4xx< 1%
  • HTTP 5xx< 0.1%
  • Kafka Failures< 0.01%
  • Oracle API Failures< 0.5%

Availability

  • Service Uptime99.95%
  • Database FailoverRTO < 4 hours
  • Kafka FailoverRTO < 15 min
  • Cache RecoveryRTO < 10 min

Operational Objective

  • Keep user-facing API latency within defined SLA thresholds under expected transaction volume.
  • Protect downstream Oracle and Kafka dependencies with healthy throughput and low failure rates.
  • Maintain availability targets and recovery objectives for order processing and batch operations.
